# Day03 任务保存器

## 项目说明

本项目实现了一个基于 JSON 文件的任务保存器，
可以新增任务、保存任务到本地文件、读取任务并打印。

## 文件说明

- `task_storage.py` — 任务保存器主程序
- `tasks.json` — 本地任务数据文件，由程序自动生成和更新

## 作业怎么运行

在终端进入 week01_day03 目录后运行：

python task_storage.py

每运行一次，tasks.json 里会多一条任务记录。
运行两次后打开 tasks.json，可以看到文件里有两条相同的任务，
这证明数据被持久化保存了下来，程序关闭后数据不会消失。

## 今天学了什么

### 函数的作用是什么

函数是把一段逻辑打包起来，方便反复调用，不用重复写同样的代码。
本项目一共定义了四个函数，各自负责一件事：

- `load_tasks()` — 从 tasks.json 读取已有任务列表，
  文件不存在时返回空列表，不报错退出
- `save_tasks(tasks)` — 把当前任务列表写入 tasks.json 保存
- `add_task(tasks, title)` — 创建一个新任务字典并追加到列表末尾
- `show_tasks(tasks)` — 遍历列表，打印每个任务的标题和状态

### JSON 文件保存了什么

tasks.json 保存的是一个列表套字典的结构，每个字典代表一个任务，
包含 title（任务标题）和 status（任务状态）两个字段，例如：

[
  {
    "title": "学习JSON文件保存",
    "status": "todo"
  }
]

每次运行程序，列表里会新增一条记录。
使用 ensure_ascii=False 让中文正常显示，indent=2 让文件格式化缩进易读。

## 遇到了什么问题

-问题一：
    调用 load_tasks() 时没有用变量接住返回值，
    直接写成 load_tasks()，导致后面的 tasks 变量不存在，
    报错 NameError: name 'tasks' is not defined。

-问题二：​ 
    运行两次后终端输出看起来一样，
    以为代码有问题，后来发现要去看 tasks.json 文件的内容，
    文件里的任务条数才是验证持久化是否成功的依据。

-问题三：​ 
    对 task 和 tasks 的单复数感到困惑，
    不确定函数体里的 task 对应的是什么。

## 是怎么解决的

-问题一： 
    把 load_tasks() 改成 tasks = load_tasks()，
    用变量接住函数的返回值，后面才能正常使用 tasks。

-问题二：
    理解了终端输出和文件内容是两回事，
    程序每次运行都会先读取文件已有内容再追加，
    变化体现在文件里，不在终端输出上。

-问题三：
    理解了 task 是单个任务字典，tasks 是装了多个任务的列表，
    单复数只是命名习惯，帮助人类读代码时一眼看懂，
    Python 本身不做任何区分。
